Maaloma — a paid course platform that lives inside Telegram.

A freelance delivery for a real client: instead of subscribing to an LMS, students browse the catalogue on the website and get their lessons from a Telegram bot that only answers approved, paid subscribers. The bot ships with its own admin panel, so the client runs the whole business from a chat — no dashboard to maintain.

What it does

Subscription, delivery and administration — all in one bot

The client sells access, the bot enforces it. Every item below is implemented in the delivered code.

◉

Paid access gating

Only approved users with an active subscription can open a lesson. Every request re-checks access against SQLite before a file is sent.

⚙

Admin panel inside the chat

Courses, lessons, fields and users are managed through guided bot conversations — no separate CMS to host, secure or teach.

⚿

Encrypted content links

Lesson links are stored encrypted with Fernet and decrypted only for authorised users, so forwarded messages never leak the source file.

✎

Signed callbacks

Inline buttons carry signed tokens instead of raw IDs, preventing tampered payloads from reaching admin or download actions.

⇪

Large file delivery

Big lessons are sent in chunks with a live progress bar, transfer speed and ETA, then cleaned up from disk automatically.

◎

Broadcast and support

The client sends announcements to all approved users and replies to student messages from a threaded support inbox.

Under the hood

One Python process, one database file

Access flow

Every state-changing action — approving a user, adding a lesson, sending a broadcast — is restricted to admins and recorded with the admin id that performed it.

Implementation notes

  • Single-file SQLite store. Ten tables cover users, courses, lessons, admins, messages, callback tokens and cached file references — easy to back up, no server to run.
  • Content at rest. Lesson links are encrypted with Fernet; the key lives in the environment, never in the code or the database.
  • Callback integrity. Inline buttons carry short-lived signed tokens, verified before any action runs.
  • Rate limiting. A per-user sliding window keeps one student from flooding the bot or the client's bandwidth.
  • Big uploads. Telegram's 50 MB limit is handled by splitting files, tracking progress and cleaning up temporary files.
  • Marketing site. Static HTML, CSS and JavaScript with Bootstrap 5 in RTL, a JSON catalogue and no build step.
